# خارطة تنفيذ NOVA Marketplace

## منجز وقابل للاختبار محليًا

- [x] Django REST API وJWT وصلاحيات وعزل بيانات المستخدمين.
- [x] Next.js + TypeScript بواجهة عربية متجاوبة وBFF آمن للجلسة.
- [x] Expo + React Native لتطبيق Android وiOS مع SecureStore.
- [x] تسجيل ودخول وعناوين وتصنيفات وبحث وتفاصيل منتجات ومفضلة.
- [x] صور ومتغيرات المنتجات ومخزون وتقييمات ومراجعات.
- [x] سلة وكميات وكوبونات وضريبة وشحن وCheckout.
- [x] طلبات وفواتير وتتبع وإلغاء وإرجاع وإعادة المخزون.
- [x] Payment model وWebhook موقّع وIdempotency ودفع Sandbox.
- [x] Shipment model وتتبع وشحن Sandbox.
- [x] SAR وUSD وAED وأسعار صرف قابلة للإدارة وتثبيت العملة في الطلب.
- [x] إشعارات داخلية، تسجيل أجهزة Push، وبريد Console/SMTP قابل للإعداد.
- [x] تخزين صور محلي أو S3-compatible، وWhiteNoise للملفات الثابتة.
- [x] اختبارات API وواجهة حية، Lint/Build، فحص Expo، Android/iOS bundles، واختبار تحميل Smoke.
- [x] Dockerfiles وCompose مع PostgreSQL، Health Checks، مراقبة Sentry اختيارية، وسكربت نسخ احتياطي.
- [x] لوحة قيادة مخزون للموظفين مع حركات الأصناف، الدُفعات، الصلاحية، التنبيهات والتوقع المبسط للنفاد.
- [x] محلل توصيات محلي مع تكامل OpenAI اختياري ومخرجات منظمة، دون إرسال بيانات العملاء.
- [x] مراقب دوري مستقل في Docker لإرسال التنبيهات الجديدة إلى الموظفين.

## مطلوب قبل الإطلاق التجاري

- [ ] اختيار دولة/دول الإطلاق واعتماد متطلبات الضريبة والفاتورة والخصوصية والإرجاع.
- [ ] اختيار بوابة الدفع وتنفيذ Adapter الحقيقي واختباره في Sandbox الخاص بالمزود ثم الإنتاج.
- [ ] اختيار شركة الشحن وتنفيذ الأسعار وإنشاء الشحنات وتحديث التتبع الحقيقي.
- [ ] إدخال حسابات S3/CDN وSMTP وSentry ومزود Push واختبارها بمفاتيح فعلية.
- [ ] ترجمة بشرية كاملة للواجهة والكتالوج والبريد والمحتوى القانوني لكل لغة مستهدفة.
- [ ] وضع المهام البطيئة في Queue مثل Celery/Redis عند الحاجة التشغيلية.
- [ ] إعداد نطاق وTLS وReverse Proxy وCI/CD وإدارة أسرار ومراقبة وتنبيهات.
- [ ] جدولة النسخ الاحتياطي واختبار الاستعادة وخطة التعافي من الأعطال.
- [ ] اختبار اختراق ومراجعة OWASP واختبار تحميل وفق أرقام المستخدمين المتوقعة.
- [ ] اختبار تطبيقات الجوال على أجهزة فعلية وتجهيز شهادات ومتطلبات App Store وGoogle Play.
- [ ] بعد توفر بيانات تاريخية كافية: معايرة تنبؤ الطلب موسميًا، قياس دقته، وإضافة موافقات بشرية قبل أي طلب توريد آلي.

## ترتيب القرار المقترح

1. تحديد السوق الأول وسياساته.
2. اختيار الدفع والشحن والتخزين والبريد وPush.
3. ربط مفاتيح بيئة تجريبية خارجية وتنفيذ اختبارات قبول.
4. نشر Staging على PostgreSQL مُدار مع HTTPS ومراقبة.
5. تنفيذ تدقيق أمني وتحميل واستعادة نسخة احتياطية.
6. إطلاق محدود ثم توسيع الدول واللغات بناءً على بيانات فعلية.

## المشروع السابق

تم حذف تطبيق Flask القديم وملفاته وقاعدة بياناته المحلية. البنية الحالية هي المصدر الوحيد للمشروع.
